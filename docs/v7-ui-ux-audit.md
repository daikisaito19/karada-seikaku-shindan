# 実ユーザー体験のUI調査（375px実機操作）

**コード変更なし。診断ロジックはv4基準版のまま凍結。コミットなし。**

調査方法: Playwright + Chromium を**スクラッチパッドにインストール**（`package.json` は未変更）。375×667px / iPhone SE相当のUAで、本番ビルド（`next start`）に対して実際にタップ操作した。

## まず、前回レポートの訂正が2点あります

実際に画面を見て、前回 `docs/v6-src-implementation.md` で書いた内容のうち2点が誤っていたことが分かりました。どちらもご判断を左右する内容なので先に訂正します。

### 訂正1: 「めぐり不足と診断された人が『めぐり 93%』というメーターを見る」は**起きません**

4軸メーターは**軸名も数値も一切表示していません**。実際の表示はこれだけです。

```
🪫 LOW              🔋 HIGH     ← バーのみ
🚦 STUCK            🌪️ FLOW
🧊 COOL             🔥 HOT
🏜️ DRY              💧 WET
```

前回は `computeVisibleAxes` のフィールド名（`flow`）とコード内コメントを見て「めぐり」と書きましたが、**画面上に日本語の軸名は出ていません**。したがって「めぐり不足」との語の衝突は**画面上には存在しません**。

ただし、これは別のもっと大きな問題を意味します → **後述 A-1**（メーターが何を測っているか分からない）。

### 訂正2: 「100%表示が出るのは1%未満」は**過小評価でした**

前回は完全ランダム回答（=B/C/Dを75%の確率で選ぶ=ほぼ全ての症状に該当すると答える人）で測ったため0.52%でした。実際のユーザーは**該当しない項目に「A（とくにない）」を選ぶ**ため、条件が全く違います。

| 「A（該当なし）」を選ぶ率 | どれか1本が100% | うるおい100% |
|---|---|---|
| 25%（=前回の測定条件） | 1.3% | 0.5% |
| 50% | 11.6% | 5.6% |
| **60%** | **22.9%** | 12.0% |
| **70%** | **39.3%** | 22.1% |
| 80%（ブラインド人物像相当） | 61.4% | 38.7% |

**自分に当てはまる項目が3〜4割くらいの「ふつうの人」で、2〜4割が振り切れたメーターを見ます。** 前回「人物像だけのアーティファクト」と書いたのは誤りで、**実ユーザーでも十分起きます**。実測でも16タイプ中**9タイプ**がうるおい100%でした。

## A. UI上の問題

### A-1. 【最重要】4軸メーターに軸名がなく、何を測っているか分からない

見出しは「あなたの4つの軸」だけで、各バーのラベルは `🪫 LOW ←→ 🔋 HIGH` のような**英語2語のみ**。

- `🚦 STUCK ←→ 🌪️ FLOW` が「めぐり」のことだと分かる手がかりが画面上にない
- `🏜️ DRY ←→ 💧 WET` が「うるおい」だと分かるのは、たまたま09うるおい不足の人だけ
- 日本語のポップな診断で、唯一この4行だけが英語

**9軸→4メーターという設計の中核が、ユーザーには伝わっていません。**

### A-2. 【重要】単方向に塗るバーを、両端にラベルがある双方向軸に使っている

バーは常に**左から右へ塗る**実装（`width: ${value}%`）ですが、ラベルは両端にあります。このため値の解釈が視覚と一致しません。

| 実測ケース | 表示 | ユーザーがどう見えるか | 本当の意味 |
|---|---|---|---|
| 05 冷え冷え の温度 = **0%** | **バーが完全に空** | 「ゼロ／何もない」 | 「冷えが強い（COOL側の端）」 |
| 10 めぐり不足 の温度 = 50% | 半分 | 「半分しかない」 | 「温度はふつう」 |
| 09 うるおい不足 の うるおい = 25% | 4分の1 | 「少ない」 | 「乾燥寄り」(これは偶然合っている) |

**05冷え冷えの温度メーターは完全に空っぽで表示されます。** 冷えが強いほど左端に振れるはずなのに、左端には何も描かれません。スクリーンショットで確認済み。

双方向軸なら「現在位置を示すつまみ」か「中央基準の左右塗り」が必要で、現在の実装は**一方向の量メーター**のものです。

### A-3. 【重要】100%が「満点」に見える

数値は表示されていないので「100点」とは読まれませんが、**バーが端まで完全に埋まる**ため「MAX／満点／これ以上ない」と読まれます。

実際には3本が減点のみの一方向メーターなので、**100% = 「該当するサインがゼロ」**という意味です。しかし `🔋 HIGH` / `🌪️ FLOW` / `💧 WET` という右端ラベルは明確に「良い状態」を示唆しており、**「サインなし」と「優秀」が区別できません**。

そして A-2 と組み合わさると矛盾が出ます。

- **16 クセ強ミックス**: エネルギー36 / めぐり29 / 温度69 / うるおい38 → **3本が空に近い**
  - コピーは「いいとこどりで混ざっている」「一言では言い表せない個性がある」
  - 画面は「全部低い＝全部ダメ」に見える
  - 判定条件は「3系統が70%以上＝**全部強い**」なのに、**表示は真逆**

### A-4. 診断中、選択した選択肢のハイライトが一切ない

選択肢をタップすると即座に次の設問へ進む実装で、**選択状態のスタイルが存在しません**（`hover:` のみ）。

- タップした瞬間に画面が切り替わるので「押せたか」のフィードバックは `active:scale-[0.98]` の一瞬だけ
- **「ひとつ戻る」で戻ると、前回選んだ選択肢が分かりません**（4つとも同じ見た目。実測で背景色・枠色が全て `rgb(252,249,255)` / `rgb(237,225,251)` と同一であることを確認）
- 戻った意味が薄い（何を選んだか思い出せないまま選び直す）

### A-5. 進捗バーが0%から始まり、97%で終わる

| 画面 | 進捗バー |
|---|---|
| Q1 | **0%（完全に空）** |
| Q6 | 17% |
| Q30 | **97%（最後まで埋まらない）** |

`progress = qIndex / total` なので、Q1で0%、Q30で29/30=97%。**「Q30 / 30」なのにバーが埋まっていません。** 最初の1問も「まだ何も進んでいない」表示です。

## B. UX上の問題

### B-1. 【最重要】途中リロードで30問すべて消える

Q10まで答えた状態でリロード → **Q1に戻り、10問分の回答が消失**。

回答は `useState` にしか持っておらず、`localStorage` にもURLにも残していません。30問は**スマホで2〜3分かかる長さ**なので、着信・アプリ切り替え・通知タップ・誤タップでの離脱が必ず起こります。

### B-2. 【最重要】ブラウザの「戻る」でサイトから離脱する

Q16の時点でブラウザバック → **`/`（TOP）に飛び、回答は全消失**。

設問の遷移が `useState` だけで行われており履歴を積んでいないため、ブラウザバックは「1問戻る」ではなく「/diagnosisに入る前」に戻ります。**スマホでは画面端スワイプで戻るのが最も自然な操作**なので、これは高確率で踏まれます。

画面内の「ひとつ戻る」ボタンは正常に動作します（Q6→Q5を確認）が、ブラウザバックの挙動と食い違っています。

### B-3. シェアURLに回答が含まれず、共有先ではメーターが出ない

コピーされる内容（実測）:

```
【カラダ性格診断】
私は「🌸 うるおい不足」でした！
カラダにも保湿が必要。

https://karada-seikaku-shindan.vercel.app/result/uruoi-busoku
```

`?a=` が付いていないため、**受け取った人は4軸メーターを見られません**（代わりに「このリンクは共有された結果ページです」という文が出ます。これ自体は正常動作）。

自分のグラフを見せたいのに見せられない構造で、**シェアの動機と機能が噛み合っていません**。

### B-4. シェアより「もう一度診断する」が目立つ

結果画面下部のボタンの序列:

| 順 | ボタン | 見た目 |
|---|---|---|
| 1 | 結果とURLをコピーする | **白地・枠線のみ**（副ボタン） |
| 2 | もう一度診断する | **グラデーション塗り**（主ボタン） |
| 3 | トップに戻る | テキストリンク |

拡散させたい診断で、**最も目立つのが「もう一度診断する」**になっています。また SNS共有ボタン（X / LINE）も `navigator.share`（スマホのネイティブ共有シート）も未実装で、**コピー＆自分で貼り付け**が唯一の手段です。

### B-5. タップ領域が小さい箇所

| 場所 | 要素 | 実測サイズ |
|---|---|---|
| TOP フッター | この診断について | 96×**16**px |
| TOP フッター | プライバシーポリシー | 120×**16**px |
| TOP フッター | 利用規約 | 48×**16**px |
| 結果画面 | トップに戻る | 343×**32**px |

推奨44pxに対して16〜32px。**規約・プライバシーポリシーへの到達性が低い**のは、公開サイトとしては直しておきたい箇所です。

設問の選択肢ボタン・CTA（343×56px）・コピーボタンは問題ありません。
