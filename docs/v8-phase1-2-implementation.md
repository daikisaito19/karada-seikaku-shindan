### Phase 2 — 診断途中のUX

`DiagnosisFlow.tsx` を `useSyncExternalStore` ベースに書き換えました。状態のソースを2つに整理しています。

- **現在の設問番号** … URLの `?q=`（1設問 = 1履歴エントリ）
- **回答** … メモリ上の配列。`localStorage` へは**ミラーするだけ**

**回答をメモリで持つのが要点**です。localStorageが使えない環境でも「その場の診断は最後まで通る（復元だけができない）」という縮退になります。

#### 1. 回答の永続化

- キー `karada-shindan:progress:v1`、値 `{v:1, q:11, answers:"AAAAABCABD"}`
- 復元条件: **`?q=` 付きで来たとき**（リロード・タブ復帰）だけ復元する
- `/diagnosis` に素で来たとき（TOPのCTA・「もう一度診断する」）は**新規スタート**として保存を消す → 古い中断データが勝手に復活しない
- **完走時に削除**（結果ページへ遷移する直前）
- 読み書き・削除をすべて `try/catch` で包み、保存形式もバリデーション（`/^[A-D]*$/`・長さ30以下・`v:1`）。壊れた値は無視して空から始まる

#### 2. ブラウザバック対応

`window.history.pushState` で1設問ごとに履歴を積み、`popstate` で設問番号を戻します。

- **Q16 →（戻る）→ Q15 →（戻る）→ Q14**
- 履歴は**1設問1エントリで最大30**。無限に増えません
- **Q1からさらに戻るとTOPへ抜けられます**（診断に閉じ込められない）
- 戻って選び直したときは `pushState` が前方履歴を切り詰めるので、**同じ設問をループしません**
- リロード時は `?q=` から位置を復元。**回答数より先を指していたら `replaceState` でURLを巻き戻す**ので、localStorageが空のまま `?q=25` を直接開いても壊れません
- 「ひとつ戻る」ボタンは `history.back()` を呼ぶよう統一。**履歴と表示がずれません**（挙動は従来どおり1問戻る、Q1では非表示）

Next.js 16 の App Router はネイティブの `history.pushState` を公式にサポートしています（`node_modules/next/dist/docs/01-app/01-getting-started/04-linking-and-navigating.md`）。`useSearchParams` は使っていないので、**`/diagnosis` は静的生成のまま**です。

#### 3. 選択状態の復元

- 選択済みの選択肢は **枠線をaccent・背景をaccent-light・太字・右端に ✓**
- `aria-pressed` を付与（スクリーンリーダー対応）
- カード下に「前回はこれを選びました。変えたい選択肢をタップしてください。」
- 別の選択肢をタップすれば**上書きして次へ進む**。それ以降の回答は保持される（設問間に分岐がないため、やり直す必要がない）
