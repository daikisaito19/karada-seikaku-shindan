## 5. 「めぐり」と「流れ」

Phase 3-1 で4軸名を「流れ」（ST/STA系）にしたのを受けて、**3つの語を別々の役割に固定**しました。

| 語 | 役割 | 結果コピー内での出現箇所（変更後） |
|---|---|---|
| **めぐり** | **10のタイプ名専用** | `name: "めぐり不足"` の**1箇所のみ** |
| **流れ** | **4軸メーターの「流れ」= ST/STA = 07の領域** | 07のcatchCopy「流れが止まると調子が落ちる。」/ 07のcharges「深呼吸やストレッチで**流れ**をつくる」の**2箇所のみ** |
| **巡り** | 使わない | **0箇所**（07のcharges「巡りをつくる」→「流れをつくる」へ） |

機械的に確認した結果:

```
流れ: 07カラダ渋滞.catchCopy =「流れが止まると調子が落ちる。」
流れ: 07カラダ渋滞.charges  =「深呼吸やストレッチで流れをつくる」
めぐり: 10めぐり不足.name   =「めぐり不足」
（巡り: 0件）
```

**04 むくみストックの「軽いストレッチや散歩でめぐりを促す」は「溜めこまない」へ変更しました。** 機械的に消したのではなく、04の中心概念が「溜め込み」であって「めぐり」でも「流れ」でもないためです。この変更で、「めぐり」が3つの別の意味で使われる状態が解消されました。

**10 めぐり不足を「流れが悪い」とは説明していません。** catchCopy「栄養・血・元気をチャージ。」lead「パワーの元になる栄養が、ちょっと足りていないかもしれない」features「ちゃんと食べないと、力が出ない」と、**一貫して「材料が足りない」方向**で書いています。

## 8. 未解決事項（意図的に残したもの）

### (1) 10 めぐり不足は、4軸メーターだけでは表現できない【Phase 3-1からの継続課題】

**今回もロジックには手を付けていません。**

計算式 `moisture = 100 - (BL + JIN)/2` により、10のprimary軸であるBLは**うるおいメーター**に入ります。実測ではBL=100 / JIN=0 で **うるおい = 50 =「まんなか」**。結果として、めぐり不足の人の4軸は

> エネルギー: かなりHIGH寄り / 流れ: FLOW寄り / 温度: COOL寄り / うるおい: まんなか

となり、**4軸のどこにも「足りていない」が出ません**。

今回のコピー修正で、**文章の側では「材料が足りない」が明確に伝わる**ようになりました（catchCopy「栄養・血・元気をチャージ。」lead「パワーの元になる栄養が、ちょっと足りていない」features「ちゃんと食べないと、力が出ない」）。**メーターとコピーが噛み合っていない状態ですが、解消するには4軸計算式かタイプ設計を変える必要があり、どちらも凍結対象**です。今後のUX課題として残します。

上記3のとおり、**内部軸との整合を優先した結果**です。差し戻し可能です。
