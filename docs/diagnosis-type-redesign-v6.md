## 先に結論 (F. 最終判断)

**現在の16タイプは、実装を確定してよい状態ではない。タイプ設計そのものを作り直すべき。**

根拠は好みや感覚ではなく、実測した4つの構造的欠陥。

### 欠陥1: ロジックを知らずに答えると、6タイプが外れる

これまでの「16/16一致」という検証結果は無効だった。理想回答を、私がスコアリングを見ながらそのタイプに着地するまで調整して作っていたため(詳細はE章)。

そこで**スコアもゲートも一切見ず、タイプ説明と設問文だけを読んで素直に答えた回答**を16タイプ分作り、一度もチューニングせずエンジンに通した結果:

| | 的中 |
|---|---|
| 調整済みペルソナ(循環評価) | 16 / 16 |
| **ブラインドペルソナ(独立評価)** | **10 / 16** |

外れた6件: 充電下手→電池切れ / 冷え冷え→スロースタート / うるおい不足→めぐり不足 / 夜型スイッチ→クセ強ミックス / 波乗り→カラダ渋滞 / クセ強ミックス→うるおい不足。
**ご指摘の「重なっている」タイプと、ほぼ完全に一致している。**

### 欠陥2: 特徴を強く出すほど、そのタイプから弾かれる

充電下手のブラインド回答はQI(元気のなさ)82%と極めて高いのに、充電下手にならなかった。N=80000で軸の強さ別の着地率を測ると:

```
充電下手になる確率   QI 50-59%: 48.2%  →  60-69%: 43.8%  →  70-79%: 21.6%  ← 下がる
電池切れになる確率   QI 50-59%:  0.0%  →  60-69%: 18.2%  →  70-79%: 35.1%  ← 吸収
```

原因は `SP >= QI - 12` という**軸同士の引き算**で01と02を分けていること。QIが高いほどSPに要求される水準が跳ね上がる。**「疲れやすい」と正直に答えるほど「充電下手」から遠ざかる**という、閾値調整では絶対に直らない欠陥。

### 欠陥3: 「〜でないこと」で定義されたタイプには、決定打の設問が存在しない

設問の選択肢ごとに「それを選ぶとそのタイプになる確率がどれだけ上がるか」を実測(N=60000)。各タイプの最大の決定打:

| タイプ | 決定打 | 押し上げ幅 |
|---|---|---|
| 食後スリープ | Q2=C | +25.1pt |
| スロースタート | Q29=C | +16.5pt |
| うるおい不足 | Q28=D | +12.4pt |
| 頭ぐるぐる | Q24=D | +8.8pt |
| 常時アクセル | Q22=A | +6.9pt |
| **イライラ充満** | Q9=B | **+1.8pt** |
| **電池切れ** | Q10=B | **+1.3pt** |

イライラ充満と電池切れだけ決定打が無い。この2つだけが肯定条件ではなく「STAが低い」「SPがQIより低い」という**否定形**で定義されているため。**選べばそのタイプになる設問が1問も無いタイプは、ユーザーから見れば存在しない。**

### 欠陥4: 設問が構造的に重複している

各設問を「どの軸にどれだけ加点するか」のベクトルとみなし、コサイン類似度を測った結果:

| 設問ペア | 類似度 | 意味 |
|---|---|---|
| **Q6「夏」 × Q19「汗」** | **1.00** | 軸ベクトルが完全一致。違う言葉で同じものを2回聞いている |
| **Q2「食後」 × Q4「甘いもの」** | **0.99** | ほぼ同一 |
| Q8「嫌なこと」 × Q16「朝と夜」 | 0.95 | 無関係な設問なのに同じ軸を同じ比率で押している |
| Q7「ストレス」 × Q30「欲しいもの」 | 0.93 | |
| Q18「天気」 × Q27「むくみ」 | 0.93 | |
| Q21「爪や髪」 × Q28「乾燥」 | 0.89 | **乾燥が2タイプを同時に押し上げている原因** |

30問のうち、類似度0.7以上のペアが**36組**存在する。

### なぜ閾値調整では直らないのか

根本原因は、**重なることが前提の東洋医学8軸を、重なってはいけない16タイプに直接マッピングしている**こと。気虚と血虚は同時に起きるし、陰虚と血虚はどちらも「乾き」として現れる。その重なりを止めるために「〜でないこと」「軸の引き算」「他タイプの除外条件」を継ぎ足した結果が欠陥1〜3。

したがって以下は、**構造から作り直す案**である。

## D. 診断ロジックの構造 — 二層構造の提案

### 現在の構造

```
30問 → 8軸スコア → 16タイプ
                    ↑ ここで無理が出ている
```

8軸が得意なのは「**どのテーマが主役か**」の判定。苦手なのは「**同じテーマの中の種類の違い**」。
イライラ充満/頭ぐるぐる/常時アクセルは3つとも「ストレスが多い」点で同じなので、STの大小では原理的に分けられない。分けるべきは「どこに出るか」という**別の次元**である。

### 提案する構造

```
30問 ─┬→ [層1] 9軸スコア ──→ 4軸メーター表示・東洋医学的な裏づけ
      │            │
      │            └→ 系統スコア(4つ) ─┐
      │                                  ├→ 16タイプ
      └→ [層2] タイプ固有シグナル ──────┘
```

- **層1 (9軸)**: 4軸メーターの表示、結果ページの東洋医学的な説明、そして「どの系統か」の判定まで担当する。
- **層2 (シグナル)**: 系統の中でどのタイプかを決める。8軸が苦手な部分だけを、専用設問で直接聞く。

### 提案1: 8軸を9軸に分割する

現在、BL(血虚)とYIN(陰虚)が両方とも「乾き」を表していることが、うるおい不足・ほてほて・めぐり不足の三つ巴の原因になっている(ご指摘の項目4と5)。ここを分離する。

| 軸 | 東洋医学 | 意味するもの | 代表する体感 | 主タイプ |
|---|---|---|---|---|
| QI | 気虚 | 元気の**総量**が足りない | だるい、疲れが抜けない | 01 / 02 |
| SP | 脾気虚 | **消化**の負担 | 食後に重い、眠い | 03 |
| ST | 気滞 | ストレスで**詰まる** | 張る、こる、モヤモヤ | 07 / 08 / 11 / 14 |
| BL | 血虚 | **血・栄養**が足りない | 顔色、立ちくらみ、爪・髪 | 10 |
| **JIN**(新) | 津液不足 | **潤い・水分**が足りない | 肌・唇・喉・目の乾燥 | 09 |
| YANG | 陽虚 | **熱が足りない** | 冷える | 05 |
| YIN | 陰虚内熱 | **熱がこもる** | ほてる、寝汗、暑がり | 06 |
| DAM | 痰湿 | 水分が**停滞**する | むくむ、重だるい | 04 |
| STA | 血瘀 | めぐりが**停滞**する | こり、アザ | 07 |

これにより **9軸のうち9つが、それぞれ1つのタイプの主軸**になる。現在のように1つの軸を複数タイプが奪い合う状態が解消される。

4軸メーターの計算式:
- エネルギー = 100 − QI
- めぐり = 100 − 平均(ST, STA)
- 温度 = 50 + (YIN − YANG) / 2 ← YINが純粋な「熱」になるため、現在より正確になる
- うるおい = 100 − 平均(BL, JIN)

### 提案2: 9軸を4系統に束ねる (重複なし)

| 系統 | 含む軸 | 系統スコア | 所属タイプ |
|---|---|---|---|
| **エネルギー系** | QI, BL | max(QI, BL) | 01 充電下手 / 02 電池切れ / 13 スロースタート / 10 めぐり不足 |
| **ストレス系** | ST, STA | max(ST, STA) | 07 カラダ渋滞 / 08 イライラ充満 / 11 頭ぐるぐる / 14 常時アクセル |
| **水分・消化系** | SP, DAM, JIN | max(SP, DAM, JIN) | 03 食後スリープ / 04 むくみストック / 09 うるおい不足 |
| **温度・リズム系** | YANG, YIN | max(YANG, YIN) | 05 冷え冷え / 06 ほてほて / 12 夜型スイッチ |

**どの軸も1つの系統にしか属さない。** これにより「めぐり不足(BL=エネルギー系)」と「うるおい不足(JIN=水分系)」は、系統の時点で分かれる。ご指摘の項目5が構造的に解決する。

### 提案3: 系統内は「識別シグナル設問」1問で決める

各系統に、その系統専用の識別設問を1問置く。**4択すべてが系統スコアを等しく押し上げ、どのタイプになるかは選択肢の識別情報だけが決める。** これにより系統内でのスコアの奪い合いが構造的に発生しなくなる。

| 系統 | 識別シグナル設問 | 選択肢 → タイプ |
|---|---|---|
| エネルギー系 | **NEW-A**「疲れているなと感じるのは、どんなときが多い？」 | 朝だけ重い→13 / 休んでも抜けない→01 / 常に残量が少ない→02 / ふらつく・顔色→10 |
| ストレス系 | **NEW-B**「ストレスがかかったとき、最初に出るのは？」 | 体が固まる→07 / イラッとする→08 / 何度も考える→11 / 動いて埋める→14 |
| 水分・消化系 | **NEW-C**「体が重くなるのは、どんなとき？」 | 食べたあと→03 / 夕方や天気の悪い日→04 / 重くならず乾く→09 |
| 温度・リズム系 | **NEW-D**「体温やだるさで気になるのは？」 | 手足やお腹が冷える→05 / 顔や上半身が熱い→06 / 夜に目が冴える→12 |

### 判定アルゴリズム

```
1. 9軸スコアを算出 (層1)
2. 系統スコア4つを算出し、降順に並べる
3. [16 クセ強ミックス] 上位3系統がすべて閾値以上 → 16 で確定
4. [15 波乗り] 上位2系統の差が僅差 かつ Q26で変動を自己申告 → 15 で確定
5. 最上位の系統を採用
6. その系統の識別シグナルの回答でタイプを確定
7. シグナルが「特にない」の場合のみ、系統内の副軸の大小で確定
```

**ステップ7により、誰も判定から漏れない。** 現在の「どのゲートも通らなかった人＝クセ強ミックス」という受け皿が不要になる。

### この構造が解決すること

| 欠陥 | 解決 |
|---|---|
| 1. ブラインドで10/16 | 系統判定は多数の設問の合計、系統内は専用1問。どちらも自然な回答が素直に効く |
| 2. 強く出すほど弾かれる | 軸の引き算(`SP>=QI-12`)を全廃。軸は単調に効く |
| 3. 決定打の無いタイプ | 全16タイプが肯定的な識別シグナルを持つ |
| 4. 設問の重複 | 1設問1軸を原則化(C章) |
| Q2への過剰依存 | Q2はSP軸を作る4問のうちの1問に降格 |

### 検討したが採らなかった案

| 案 | 不採用の理由 |
|---|---|
| 閾値の再調整だけで対応 | 欠陥2(軸の引き算)と欠陥3(否定形の定義)は閾値をどう動かしても直らない |
| 8軸を捨てて行動パターンのみで判定 | 東洋医学的な裏づけと4軸メーターが失われ、企画の核が消える |
| タイプ数を16から減らす | 16という数はMBTI的な面白さの中核。減らさずに解けるので減らさない |
| 全タイプに専用シグナル設問を1問ずつ(16問) | 30問中16問が識別専用になり「診断されている感」が強くなりすぎる。系統単位の4問で足りる |

## A. 16タイプの再定義

各タイプについて10項目。**「このタイプにならない条件」** は、隣接タイプとの境界を本人が読んで納得するための記述であり、同時に実装時の検証項目でもある。

### 01 🔋 充電下手

| 項目 | 内容 |
|---|---|
| **キャッチコピー** | 動けるのに、戻らない。 |
| **核心** | 出力は出せる。でも充電が入らない。ケーブルが断線しているタイプ。 |
| **身体感覚** | 寝ても疲れが残る。休んだ翌日も回復した感じがしない。夕方に一度切れる。 |
| **行動パターン** | 予定は普通にこなす。休日は寝て終わるが、それでも回復しない。 |
| **ストレス時** | 無理をしてでも動こうとする。止まると戻れなくなる感覚がある。 |
| **回復時** | 時間をかけて休めば戻る。ただし「寝る」だけでは足りず、質のいい休みが要る。 |
| **決定的な違い** | 02と違い**頑張るという選択肢がある**。13と違い**朝だけの問題ではない**。14と違い**動きたくて動いているわけではない**。 |
| **9軸との関係** | 主: QI(高) / 副: SP(中) — エネルギー系 |
| **ならない条件** | 朝だけがつらくて動き出せば平気な人(→13)。そもそも頑張る余力が無い人(→02)。ふらつきや顔色が主訴の人(→10)。 |

| 項目 | 内容 |
|---|---|
| **キャッチコピー** | 流れてはいる。運ぶ中身が足りない。 |

> **名前についての注意**: 「めぐり不足」という語は本来「循環が悪い」と読めるが、循環の停滞は07カラダ渋滞(血瘀)の担当である。中心概念を**「材料不足」**に確定させる以上、名前と意味がずれる。クセ強ミックスで同じ問題が起きているため(後述)、**改名の検討を推奨する**(案: 「ガス欠ぎみ」「燃料不足」など)。名前を維持する場合は、キャッチコピーで「流れてはいる。運ぶ中身が足りない」と明示して誤読を防ぐ必要がある。

## B. 似ているタイプの境界線

各ペアについて「Aになる人 / Bになる人 / 両方に当てはまりそうなときに何を見るか」。
**「何を見るか」は、すべて具体的な設問への回答**で書いている(実装時の検証項目になる)。

|---|---|---|---|---|
| 1 | **充電下手 vs 電池切れ** | 頑張れば動ける。でも休んでも戻らない | 頑張るという選択肢が無い。動く前から足りない | **NEW-A**: 「休んだはずなのに抜けきっていない」→01 / 「何もしていなくても常に残量が少ない」→02。**疲労の強さでは分けない**(現行最大の欠陥) |

## E. ペルソナ検証方法の見直し

### 現在の検証は循環していた

ご指摘の通り。`personas.ts` の理想回答は、以下の手順で作られていた:

```
1. タイプ定義を見る
2. 回答案を作る
3. エンジンに通す
4. 違うタイプが出る
5. → 回答を変える  ← ここが問題
6. 4〜5を繰り返して、そのタイプが出るまで調整
7. 「16/16一致」と報告
```

**ステップ5で、私はスコアとゲートを見ながら回答を書き換えていた。** これは「テストが答えを見てから採点している」のと同じで、ロジックの正しさを何も証明していない。「16タイプすべてが的中」という報告は撤回する。

### 提案する検証方法

**回答を作る人(工程)が、スコアリングを参照できないようにする。**

```
【工程1】タイプ定義を確定する        ← スコアリングを見ない
【工程2】30問の文面を確定する         ← スコアリングを見ない
【工程3】理想回答を作る               ← スコアリングを見ない。ここで確定し、以降変更禁止
--------------------------------- ここから先で初めてスコアリングを見る ---
【工程4】エンジンに通す
【工程5】結果を記録する               ← 外れても回答は直さない。直すのはロジックか設問
```

工程3で作った回答は**凍結**し、外れた場合に直してよいのは**ロジックまたは設問**だけ、というルールにする。回答を直した瞬間に循環が復活するため、ここは機械的に守る必要がある。

今回この方法で作ったのが `scripts/redesign-v2/blind-personas.ts` で、結果が**10/16**だった。これが現在の実力の正しい数字である。

### 追加で行うべき検証

| 検証 | 目的 | 合格基準(案) |
|---|---|---|
| ブラインド的中率 | 自然に答えたらそのタイプになるか | **16/16** |
| 1〜3問変更時の安定性 | 少しの揺れで別人にならないか | k=3で80%以上 |
| **軸の単調性** | 特徴を強く出すほどそのタイプに近づくか | **全タイプで単調増加**(現在01が違反) |
| 設問の重複度 | 同じことを何度も聞いていないか | コサイン類似度0.9以上のペアがゼロ |
| 1問あたりの決定力 | 1問でタイプが決まっていないか | 識別シグナル4問以外は影響10pt未満 |
| 第三者によるブラインド回答 | 私以外の人が答えても的中するか | **実装後、実際に数人に答えてもらう**のが理想 |

最後の項目が本来もっとも信頼できる検証である。私が書いたブラインド回答も「私がタイプ説明をどう読んだか」という偏りは避けられないため、**実装後に実際の人間の回答で確認する工程**を入れることを推奨する。

## F. 最終判断(詳細)

### 判断: タイプ設計から作り直すべき

「実装を確定してよいか」に対する答えは **No**。理由を、ご提示の最優先5項目に沿って整理する。

| 最優先事項 | 現状 | 評価 |
|---|---|---|
| 1. 結果を読んで「これ私じゃん」と思える | **ブラインド検証で10/16**。自然に答えた6タイプが別のタイプになる | ❌ 未達 |
| 2. 似たタイプとの違いが明確 | イライラ充満/頭ぐるぐる/常時アクセルはST高低だけで分けており、**原理的に分離不能**。イライラ充満には決定打の設問が存在しない(+1.8pt) | ❌ 未達 |
| 3. 30問に答えた結果としての納得感 | 食後スリープが実質Q2の1問で決まる(影響25.1pt、ランダム回答でも20%が着地)。**30問答えた意味が薄い** | ❌ 未達 |
| 4. 1〜3問の揺れで別タイプにならない | ブラインド回答での安定性はk=3で61〜99%。**ばらつきが大きく、特に境界付近のタイプが不安定** | △ 部分的 |
| 5. 友達に共有したくなる | クセ強ミックスが「どれにも当てはまらなかった人」になっており、**共有したくなる結果になっていない**(名前と実装が正反対) | ❌ 未達 |

### 「直せば済む」のか「作り直すべき」なのか

閾値調整で直せるものと、構造を変えないと直せないものを分けると:

| 問題 | 閾値調整で直るか |
|---|---|
| ランダム回答時の分布の偏り | ✅ 直る(すでに改善済み) |
| 食後スリープの出現率が高い | △ 一部直るが、Q2の決定力は残る |
| **特徴を強く出すほど弾かれる(欠陥2)** | ❌ **直らない**。軸の引き算という構造が原因 |
| **決定打の無いタイプ(欠陥3)** | ❌ **直らない**。否定形の定義という構造が原因 |
| **ストレス系3タイプの分離** | ❌ **直らない**。1つの軸の大小では3つに分けられない |
| **うるおい不足とほてほての分離** | ❌ **直らない**。BLとYINが両方「乾き」を持つ軸構造が原因 |
| **クセ強ミックスの意味の逆転** | ❌ **直らない**。フォールバックという位置づけ自体が原因 |

**7項目中5項目が、閾値では直らない。** したがって、いま実装を確定すると、これらは仕様として固定されてしまう。

### 作り直しの規模

ただし、作り直すと言っても白紙からではない。

| 資産 | 扱い |
|---|---|
| 16タイプの名前・順番・世界観 | **そのまま使える**(A章は名前を1つも変えていない。めぐり不足のみ改名を提案) |
| 30問のうち26問 | **そのまま、またはスコア配分の修正だけで使える** |
| 8軸の考え方・4軸メーター | **そのまま使える**(BLを2つに分ける9軸化のみ) |
| UIコンポーネント・ページ構成 | **そのまま使える** |
| `scoring.ts` の判定部分 | 書き換えが必要 |
| `typeDefs.ts` | 全面書き換え |

**差し替えが必要な設問は4問、全面書き換えが必要なファイルは実質1つ。** 構造の変更は大きいが、実装量は大きくない。

### 推奨する進め方

```
【今ここ】本レポートのレビュー・方針決定
   ↓
【次】scripts/redesign-v3/ にプロトタイプのみ作成 (src/ には触れない)
      ・新30問、9軸、系統判定、識別シグナル
      ・ブラインドペルソナ16件を通して的中率を測る (現在10/16 → 目標16/16)
      ・単調性・安定性・重複度を測る
   ↓
【通れば】src/ に実装
【通らなければ】設計に戻る
```

プロトタイプ段階で数字が出なければ設計に戻れるため、**ここで作り直しても手戻りのリスクは小さい**。逆に、いま実装を確定してから同じ問題に気づくと、UIとコピーまで含めた手戻りになる。

### ご判断いただきたい点

1. **D章の二層構造(9軸＋系統判定＋識別シグナル)で進めてよいか** — 今回の提案の本体
2. **BL軸をBL(血・栄養)とJIN(潤い・水分)に分割してよいか** — うるおい不足とめぐり不足の分離に必須
3. **クセ強ミックスを「3系統以上が強い人」に再定義してよいか** — 意味が現在と正反対になる
4. **めぐり不足の改名を検討するか** — 中心概念を「材料不足」に確定すると、名前の「めぐり」と意味がずれる
5. **識別シグナル4問(NEW-A〜D)の文面** — タイプをほぼ直接聞くため「診断されている感」が出る。許容範囲の判断が必要
6. **プロトタイプ検証(scripts/redesign-v3/)に進んでよいか**
