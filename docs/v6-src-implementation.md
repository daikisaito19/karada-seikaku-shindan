## 5. 「100%表示が不自然」問題 — UI側で解決する余地の確認

**まだ何も変更していません。** 現状の確認と選択肢の提示だけです。

### 実測: ランダム回答での振り切れはごく稀

| メーター | 100%到達 | 0%到達 | 平均 |
|---|---|---|---|
| エネルギー | 0.86% | 0.00% | 69.7 |
| めぐり | 0.00% | 0.00% | 58.1 |
| 温度 | 0.01% | 0.02% | 50.0 |
| うるおい | 0.52% | 0.03% | 55.7 |

**実ユーザーで100%が出るのは1%未満。** 上の表でブラインド人物像の11/16がうるおい100%になっているのは、人物像が「自分の特徴以外は全部A(該当なし)」という理想化された回答をしているためで、実際の回答分布ではほぼ起きない。

### ただし、構造的なズレは残っている

4メーターのうち3本は**減点のみの一方向メーター**である。

| メーター | 式 | 「100%」の意味 |
|---|---|---|
| エネルギー | `100 - QI` | 気虚のサインがゼロ |
| めぐり | `100 - (ST+STA)/2` | 滞りのサインがゼロ |
| うるおい | `100 - (BL+JIN)/2` | 乾燥のサインがゼロ |
| 温度 | `50 + (YIN-YANG)/2` | (双方向。中央50が普通) |

つまり**「100% = 優秀」ではなく「100% = 該当サインなし」**。ラベルが `🏜️DRY ←→ 💧WET` なので、ユーザーは「自分は人より潤っている」と読んでしまう。これが不自然さの正体で、**BL軸やJIN軸を触っても直らない**（メーターの意味論の問題なので）。

### UI/コピーでの解決案（未実装・ご判断待ち）

| 案 | 内容 | 影響範囲 |
|---|---|---|
| **A. ラベルを非対称にする** | `🏜️ 乾燥サインあり ←→ 💧 気になるサインなし` のように、右端を「良い」ではなく「サインなし」と書く | `AxisMeter.tsx` のラベル4箇所 |
| **B. 目盛りを足す** | 中央に「ふつう」の目印を置き、右端を「上限」に見せない | `AxisMeter.tsx` |
| **C. 数値を出さない** | %表示をやめてバーの長さだけにする。100という数字が消えれば「満点」と誤読されない | `AxisMeter.tsx` |
| **D. 一言添える** | メーター下に「高い＝気になるサインが少ない、という意味です」を小さく添える | 結果ページ1箇所 |

**A + D の併用**が最小の変更で意味のズレを解消できる、というのが私の見立てです。ただし Step 5 でコピー・UIの変更を禁止いただいているので、**手をつけていません**。

### 実装後に見えた「めぐり」の重複（判断材料として）

実際の結果画面で確認すると、「めぐり」という語が4箇所で別の意味に使われている。

| 場所 | 語 | 指しているもの |
|---|---|---|
| タイプ10の名前 | **めぐり不足** | BL軸 = 血・栄養という**材料の不足** |
| タイプ07 カラダ渋滞 の charges | 「巡りをつくる」 | STA軸 = **流れの滞り** |
| タイプ09 うるおい不足 の charges | 「めぐりを促す」 | JIN軸まわり |
| 4軸メーターの2本目のラベル | **めぐり** | ST/STA軸 = **カラダ渋滞** |

**めぐり不足と診断された人が、同じ画面で「めぐり 93%」というメーターを見る**（上の実測表のとおり）。タイプ10のリードコピーは「パワーの元になる栄養が、ちょっと足りていない」で**すでに材料不足の意味**なので、コピーを直す必要はなく、**名前とメーターのラベルのどちらかが重複を解消すれば済む**。
